# وكيل البرمجة (Dev Agent) — داخل الشات العادي

## القرارات المثبتة
- **الذكاء الاصطناعي**: `chat-alibaba` فقط (نفس موديل الشات الأساسي). لا AI SDK ولا Gateway آخر.
- **مفيش صفحات جديدة**. الوكيل يشتغل جوّا الشات العادي زي أي وكيل تاني.
- **مفيش تريمينال ظاهر ولا شجرة ملفات ولا IDE**. المستخدم يشوف رسائل الوكيل عادي.
- **النشر مش تلقائي**. الوكيل بيعدّل ويبني ويتحقق فقط. النشر يحصل **لما المستخدم يطلبه صراحة** ("انشر / deploy / علي الهوا")، وساعتها بس يظهر **رابط الموقع + سكرين شوت**. أي طلب تعديل عادي = تعديل + بناء + رسالة مختصرة بدون نشر (توفير تكلفة).
- **البنية التحتية**: Freestyle.sh.
- **المفاتيح**: تُدار من صفحة المفاتيح الإدارية الموجودة (نفس نمط `manus_keys`) — جدول `freestyle_keys` مع تدوير وfailover.

## هل Freestyle اختيار كويس؟ — أيوه، ممتاز
لأنه المزوّد الوحيد اللي بيدي في API واحد كل اللي محتاجينه:
- **VM حقيقي** بأمر `vm.exec()` → الوكيل ينفذ `npm install`, `npm run build`, `git`, أي أمر.
- **Git Filesystem** → كل مشروع ريبو حقيقي: commits، branches، rollback. يغنينا عن بناء نظام checkpoints/ملفات من الصفر.
- **Dev Server** → يشغّل Vite ويرجّع رابط معاينة حي (React 18/19 كامل، مش Babel-CDN).
- **Deploy** → نشر بأمر واحد على دومين حقيقي.
- **مجاني للأبد**: 10 VMs متزامنة + 500 ريبو — كفاية جدًا للبداية.
البدائل (E2B / Daytona) كانت هتخلينا نبني الـ Git والـ dev-server والنشر بأيدينا.

المفاتيح المطلوبة منك: `FREESTYLE_API_KEY` (يتحط من صفحة المفاتيح).

## كيف يندمج مع الشات بدون تغيير الكود الحالي

الوكيل الجديد كله في ملفات جديدة:
```text
api/dev-agent.ts                    ← نقطة الدخول الوحيدة الجديدة
src/lib/devagent/
  ├─ agentLoop.ts        حلقة التخطيط/التنفيذ/التحقق
  ├─ tools.ts            تعريف الأدوات وتنفيذها
  ├─ freestyle.ts        عميل Freestyle (VM / Git / DevServer / Deploy)
  ├─ github.ts           استيراد ودفع الريبو (git clone/push داخل الـ VM)
  ├─ supabaseSetup.ts    Supabase Management API
  ├─ screenshot.ts       لقطة الموقع بعد النشر
  └─ client.ts           بدء/متابعة المهمة من المتصفح
src/components/chat/DevAgentCard.tsx   ← كارت واحد صغير: حالة + رابط + سكرين شوت
```

الربط بالشات = **إضافة واحدة صغيرة فقط** في `agentRegistry.ts` (وكيل `@dev`) + سطر توجيه في `ChatPage.tsx` بنفس نمط `runComputerTurn` الموجود. ولو الوكيل الأساسي احتاجه، يستدعيه كأداة `dev_agent` عبر نفس نقطة الدخول. لا تعديل في أي منطق قائم.

### شكل التجربة للمستخدم
1. يكتب طلبه في الشات (أو `@dev`).
2. يشوف تحديثات نصية مختصرة: "بجهّز البيئة… بثبت الحزم… ببني… بنشر".
3. في النهاية كارت واحد فيه: **رابط الموقع** + **سكرين شوت** + زر "افتح".

## المحرك

### الأدوات المتاحة للوكيل (كلها server-side، غير ظاهرة للمستخدم)
`run_command` · `read_file` · `write_file` · `apply_patch` · `list_dir` · `search_code`
`npm_install` · `build` · `read_logs` · `git_commit`
`import_github_repo` · `create_supabase_db` · `run_migration`
`deploy` · `screenshot` · `todo_write` · `done`

### حلقة المهام العملاقة
```text
Planner  → يقسّم الطلب إلى قائمة مهام تُحفظ في dev_tasks
   ↓
Coder    → ينفذ مهمة واحدة كل دورة (يكتب ملفات + أوامر)
   ↓
Verifier → npm run build ؛ لو فشل يقرأ الخطأ ويصلحه تلقائيًا (حتى 3 محاولات)
   ↓
Commit   → commit بعد كل مهمة ناجحة → المهمة التالية
   ↓
Deploy   → نشر + سكرين شوت + إرجاع الرابط
```
الحالة كلها محفوظة في Git + قاعدة البيانات، فالمهمة تكمل حتى لو المستخدم قفل التبويب، وتُستأنف بنفس آلية الـ keepalive المستخدمة حاليًا.

### قوالب المشاريع
React 18 + Vite + TypeScript + Tailwind + shadcn (القالب الأساسي)، مع خيار Next.js وFull-stack (Vite + Supabase). المشاريع الحقيقية بتتبني وتتفحص فعليًا في الـ VM، مش معاينة وهمية.

## قاعدة البيانات (جداول جديدة فقط، بادئة `dev_`)
| الجدول | الغرض |
|---|---|
| `dev_projects` | مشروع = ريبو Freestyle + آخر رابط نشر + سكرين شوت |
| `dev_runs` | جلسة وكيل: الحالة، الـ VM، آخر نبضة |
| `dev_tasks` | قائمة المهام الفرعية وحالتها |
| `dev_events` | سجل الخطوات (للاستئناف والتشخيص) |
| `freestyle_keys` | مفاتيح Freestyle بالتدوير — نفس نمط `manus_keys` |

كل جدول بـ RLS على `auth.uid()` + GRANTs المطلوبة.

## مراحل التنفيذ
1. **الأساس**: الجداول + صفحة المفاتيح + عميل Freestyle (إنشاء VM/ريبو، `exec`, `deploy`) واختبار حقيقي.
2. **الأدوات**: تنفيذ كل الأدوات مع تحقق ومهلات.
3. **الحلقة**: Planner/Coder/Verifier فوق `chat-alibaba` مع استئناف.
4. **الربط بالشات**: `@dev` + كارت النتيجة (رابط + سكرين شوت).
5. **التكاملات**: استيراد GitHub، ثم Supabase Management API.
6. **اختبار نهائي**: طلب "اعمللي متجر React كامل مع قاعدة بيانات" من الشات لحد ما يرجع رابط شغّال.
